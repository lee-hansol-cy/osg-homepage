# Debug Journal — OSG reference-fidelity repair

## Scope
- Runtime: Bun + Vite + Three.js/CSS3D in Chromium
- User-visible defects: press motion, toggle/theme artifacts, wrong key mapping, missing wheel scroll
- Visual contract: supplied SVG and Figma CSS, desktop only

## Hypotheses
- H1: physical controls scale on hover while moving on the world Y axis, producing non-physical press motion and label drift.
- H2: toggle/theme actions mutate isolated meshes and material instances instead of a single component state, producing discontinuity and black artifacts.
- H3: the physical D-pad maps left+up to `previous` and right+down to `next`; the DOM keyboard handler is already vertical-only.

## Findings

### 2026-07-17 — physical direction mapping
- Source: `src/device.ts` current `directions` table
- Value: `left/up -> previous`, `right/down -> next`
- Interpretation: the reported horizontal-arrow scrolling is caused by the physical hit-map, not the DOM keyboard handler.
- Confirms: H3

### 2026-07-17 — UV label apparent-size drift
- Source: `src/labels.ts`
- Value: default font size is `min(104, canvas.height * 0.65)` on a fixed 512px canvas.
- Interpretation: label glyph size is derived from texture aspect ratio rather than the Figma 17px/11px source values, making physical labels appear inconsistently small.
- Confirms: source-size mapping must replace automatic fitting.

### Red phase — physical D-pad horizontal mapping
- Test: `src/controls.test.ts` — `moves the catalogue only with the vertical physical arrows`
- Command: `bun test src/controls.test.ts`
- Output: `Received: -1` for `catalogueStepForDpad("left")`; `0 pass, 1 fail`.
- Confirms: horizontal physical arrows incorrectly change catalogue focus.

### Green phase — physical D-pad horizontal mapping
- Fix: `src/controls.ts` maps only `up -> -1` and `down -> 1`; left/right return `undefined`.
- Test: `bun test src/controls.test.ts` — `1 pass, 0 fail, 4 expect() calls`.

## User-mandated fidelity checklist

The following corrections are project requirements, not optional polish:

1. Upper and lower cover curves must derive from the same source scale; no per-part visual resizing.
2. Every OSG mark uses the supplied SVG paths. Live text must never substitute for a logo.
3. Physical controls translate into their wells and return. Hover/click scaling is prohibited.
4. Active display corners remain square; only surrounding bezels may be rounded.
5. Right controls and the motion switch use the exact capsule silhouettes from the Figma export.
6. Motion and Light/Dark transitions must remain continuous and free of transient black artifacts.
7. D-pad dot arrows preserve the source orientation; only up/down navigate the vertical catalogue.
8. OSG Capsules sizes, weights, tracking, casing, and source label slots are preserved exactly.
9. Upper thickness remains 1.35 world units; lower thickness is 3.15. Outer radii are 4px upper and 16px lower; mating edges are 2px. The center hinge is tangent to the upper plane.
10. The camera lens keeps a glossy blue-violet optical core beneath a separate glass cover.
11. The lower screen accepts real mouse-wheel scrolling. Keyboard left/right never navigate it.
12. The lid logo reads as a recess and the inner badge uses reflective chrome with a visible SVG mark.
13. The upper inner face is physically recessed around the screen rather than covered by a floating frame.
14. Rounded UI elements use continuous Lisse paths; active screen interiors remain rectangular.
15. Repeated catalogue rows are componentized and keep one exact layout/type scale.
16. The 1920 × 1080 desktop frame is the only responsive target for this revision.

Additional visual rules from the review cycle:

- No product ground/contact shadow.
- Speakers are apertures, never raised studs.
- Button labels preserve the supplied capitalization (`Artworks`, `Fonts`, `Tools`).
- Body and control lettering reads as UV printing, not swollen 3D type.
- All part sizes use `world = Figma pixels / 20`; hidden depth assumptions remain configurable and documented.
- OSG Capsules is judged by visible cap height, not only CSS em size. The measured cap-height ratio is `12816 / 16376`; 17px source type fills a 13px cap slot and 11px type fills a 9px slot.
