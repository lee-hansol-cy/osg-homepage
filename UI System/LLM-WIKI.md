# OSG UI System: AI 작업 원칙

이 문서는 OSG UI System의 컴포넌트와 디자인 요소를 사용하는 AI를 위한 작업 규칙이다.

## 최우선 원칙

새로운 요소를 계속 만들어내지 말고, 이미 UI System에 존재하는 요소를 먼저 찾아 재활용한다.

기존 컴포넌트, 상태, 변형, 아이콘, 색상, 타이포그래피, 간격, 모서리, 그림자, 레이아웃 패턴으로 요구사항을 해결할 수 있다면 새 요소를 만들지 않는다. 새로운 요소의 추가는 기존 요소로 해결할 수 없다는 근거가 있을 때만 허용한다.

## 작업 순서

1. 현재 UI System의 컴포넌트와 디자인 토큰을 먼저 탐색한다.
2. 요청과 가장 가까운 기존 요소를 선택한다.
3. 기존 요소의 props, variant, size, state, 조합 방식으로 해결을 시도한다.
4. 필요한 경우 여러 기존 요소를 조합한다.
5. 그래도 해결되지 않을 때만 새 컴포넌트나 디자인 요소를 제안한다.
6. 새 요소를 추가할 경우, 재활용이 불가능했던 이유와 기존 요소와의 차이를 문서에 기록한다.

## 재활용 규칙

- 같은 시각적 역할을 하는 요소를 중복 생성하지 않는다.
- 기존 컴포넌트의 이름, API, 스타일, 토큰을 임의로 복제하거나 변형해 유사 컴포넌트를 만들지 않는다.
- 기존 컴포넌트의 사용법을 우선하고, 새 사용 사례는 가능한 한 기존 API의 조합으로 표현한다.
- 색상, 폰트, 간격, radius, shadow는 하드코딩하지 말고 기존 디자인 토큰을 사용한다.
- 기존 상태와 variant가 있으면 새 상태나 variant를 만들기 전에 그것을 재활용한다.
- 아이콘과 이미지도 새로 그리거나 생성하기 전에 기존 에셋을 확인한다.
- 이름만 다른 동일한 역할의 컴포넌트를 만들지 않는다.

## 새 요소가 정말 필요한 경우

새 컴포넌트나 디자인 요소를 추가하기 전 다음을 확인한다.

- 기존 요소의 props 또는 variant 확장으로 해결할 수 없는가?
- 기존 요소들을 조합해서 해결할 수 없는가?
- 기존 요소의 시각적 역할과 의미가 다른가?
- 같은 요소가 이미 다른 이름으로 존재하지 않는가?
- 새 요소가 앞으로 반복 사용될 가능성이 있는가?

위 질문에 대한 답과 함께 새 요소가 필요한 이유를 남긴다. 단 한 화면에서만 쓰이는 요소라면 독립 컴포넌트로 만들기보다 해당 화면 안에서 기존 요소를 조합하는 것을 우선한다.

## AI의 완료 조건

작업을 완료할 때 다음을 보고한다.

- 재활용한 기존 컴포넌트와 디자인 요소
- 사용한 variant, state, token
- 새로 만든 요소가 있다면 그 이유
- 새 요소를 만들기 전에 검토한 기존 요소

이 UI System의 목표는 요소의 수를 늘리는 것이 아니라, 일관된 시스템 안에서 기존 자산의 재사용률을 높이는 것이다.
